# Slide Draft

## 概要

箇条書きメモ・キーワードをもとに、社内共有・LT用の発表原稿を一緒に作るコマンド。

## 使い方

```sh
/draft [箇条書きメモ・キーワード・ファイルパス]
```

### 例

```sh
/draft 新CI/CDパイプライン導入。背景はデプロイ頻度を上げたかった。GitHub Actions使った。週1→1日複数回になった。 $(./memo.md) をもとにスライド原稿を作成して
```

## AIの動き（ステップ）

### STEP 1 — 発表時間だけ確認（1問のみ）

社内LT想定なので聴衆の説明は不要。
時間だけ確認して即スタート。

```md
発表時間を教えてください。
A) 5分以内（LT）
B) 10〜15分
C) 30分〜
```

> 時間がわかれば情報量とページ数の目安が決まる

| 時間     | ページ数目安 |
| -------- | ------------ |
| 5分以内  | 5〜8ページ   |
| 10〜15分 | 10〜15ページ |
| 30分〜   | 20ページ〜   |

### STEP 2 — メモの整理

- 事実確認・誤字脱字の修正
- 言いたいことの抽出と整理
- 情報の不足・矛盾があれば指摘・補完候補を提示

### STEP 3 — 構成の提案（確認あり）

以下の形式で構成案を出し、**承認を得てから原稿に進む**。

```md
## 構成案（LT 5分 / 7ページ想定）

| #   | セクション | 主な内容                       |
| --- | ---------- | ------------------------------ |
| 1   | タイトル   | CI/CDパイプライン刷新の話      |
| 2   | 背景・課題 | デプロイ頻度を上げたかった理由 |
| 3   | やったこと | GitHub Actions 導入の概要      |
| 4   | 結果       | 週1回 → 1日複数回              |
| 5   | まとめ     | 3つのポイント                  |

承認しますか？追加・変更・削除があればどうぞ。
```

### STEP 4 — 原稿執筆

承認後、Markdownで原稿を書く。

### 例: 原稿フォーマット

```md
# CI/CDパイプラインを刷新した話

## 背景

（本文...）

---

## やったこと

（本文...）

---

## 結果

（本文...）

---

## まとめ

- ポイント1
- ポイント2
- ポイント3
```

### STEP 5 — レビューと確定

- 人間が確認・修正を返す
- 反映して再提案
- 「OK」で原稿確定 → `/slide ./draft.md` で次のフェーズへ
